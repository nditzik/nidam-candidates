# scanner — סריקת המועמדים (EMA-bounce) לשחזור בענן

חבילה שמאפשרת לבנות מחדש את סריקת המועמדים שמפיקה את `candidates.json`,
בלי גישה למערכת המקורית ובלי IBKR.

## מה יש כאן

| נתיב | מה זה |
|---|---|
| `SCAN_SPEC.md` | המפרט המלא: יקום, נתונים, פרמטרים, נוסחה לכל שדה, מקרי קצה |
| `offline_scan.py` | מריץ את הסריקה על נרות מקובצי CSV. **נקודת ההתחלה לגרסת הענן** |
| `code/` | הקוד המקורי של הסריקה, כמו שהוא (עם השמטות פרטיות מסומנות `[REDACTED]`) |
| `golden/` | דוגמת אימות מהסריקה של 8.10.2026: יקום, נרות, והפלט האמיתי |
| `tools/make_golden.py` | הסקריפט שהפיק את `golden/` במחשב המקור (תיעוד בלבד) |

## הרצה

```bash
pip install -r requirements.txt
python offline_scan.py --check
```

פלט צפוי:

```
candidates.json identical to golden: True  (56/56)
pass/fail matches universe.csv for 106/106 symbols with bars
```

כתיבת הפלט לקובץ: `python offline_scan.py --out candidates.json`

## איך עוברים ל-Yahoo

ב-`offline_scan.py` מחליפים שלוש פונקציות בלבד, והלוגיקה נשארת זהה:

- `load_universe()`: רשימת המניות בסדר הסריקה, ולכל מניה ה-RVOL מקובץ המומנטום.
- `load_bars()`: נרות יומיים לחלון הסריקה ("6 M").
- `load_bars_2y()`: נרות יומיים לשנתיים, רק למועמדים, לחישוב `hist_r`.

כל נר: `date, open, high, low, close, volume`, מהישן לחדש. ראו ב-`SCAN_SPEC.md`
את הסעיף "מעבר ל-Yahoo" לדברים שישפיעו על התוצאה (סוג ההתאמה של המחיר, תאריך תחילת החלון).

## תלויות

- `pandas`, `numpy`: כל מה שצריך לסריקה עצמה.
- `ib_async`: רק לקוד המקורי שמושך מ-IBKR. לא נדרש בענן.

## מה חסר כאן בכוונה

חיבור ל-IBKR, יומן העסקאות, הדשבורד, ביצוע פקודות ונתוני חשבון לא נכללו.
`code/scan.py` מייבא חלק מהמודולים האלה, ולכן הוא מצורף **לקריאה** ולא להרצה.
הלוגיקה שלו משוכפלת ב-`offline_scan.py`, שכן רץ.
